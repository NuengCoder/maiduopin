# 2026-11-24

## 性能与商品图重构（maiduopin 买家端 MVP）

**问题**：小程序首屏卡顿 + 商品图与商品不匹配。根因是 `miniprogram/mock/data.ts` 用
`https://picsum.photos/seed/<id>/600/600` 给每件商品随机取图，首屏要发几十个图片请求，图还是随机风景照。

**方案（已落地）**
- 新增 `scripts/gen-covers.js`：纯 Node（zlib + 自写 PNG 编码器，无依赖）按品类调色板生成 16×16
  渐变 PNG，输出 base64 data URI 到 `miniprogram/mock/covers.ts`（27 条，约 18KB）。默认尺寸由
  `COVER_SIZE` 控制，`COVER_OUT` 可导出预览，`--check` 用于校验文件是否过期。
- `data.ts`：`PHOTO_BASE` 常量（空=用生成封面，填 CDN 则用 `${PHOTO_BASE}/{id}.jpg`）；
  `PRODUCT_EMOJI` 逐商品 emoji，`EMOJI_BY_CATEGORY` 兜底；`Product` 增加 `coverEmoji`/`coverTone`/`defaultSkuId`。
- 模板：`goods-card`、detail 画廊与 SKU 弹层、首页 banner 与秒杀条、flash-sale、cart、order-list、
  order-detail、checkout、group-detail、bargain-detail 全部叠加 `.cover-emoji`。
  `app.less` 新增 `.cover` / `.cover-emoji(--lg/--md/--sm)` / `.thumb-relative` / `.thumb-fill`。

**性能**
- 新增 `ProductCard = Omit<Product, 'images'|'skus'|'reviews'|'description'>`，`getHome`/`getProducts`/
  `getFavorites`/`getFlashSessions` 只回卡片字段（feed 83KB → 26KB）。只有详情页 `getProduct` 返回完整对象。
- `flash-sale.ts` 不再 `setData({ session })`（原来把整场商品再传一遍），改传 `sessionTitle`/`sessionEndAt`/`hasSession`。
- `custom-tab-bar.refresh()` 值未变时跳过 setData。
- `detail.previewImage` 只对 http(s) 图生效（data URI 不支持 previewImage）。

**NTCRANFILE.yaml**（`check` 是 ntc 保留字，快速闸门叫 `verify`）
`standalone`(默认→checks) / `install` / `typecheck` / `validate` / `pages` / `smoke` / `verify` / `checks` /
`test` / `ci` / `covers` / `covers-check` / `backend` / `landing` / `setup` / `clean` / `doctor`。
配套脚本：`scripts/backend-status.js`（列 46 个 API 契约）、`scripts/serve.js`（零依赖静态服务，5173）、
`scripts/clean.js`。CI 改为 `npm test`；`package.json` 增加 covers/covers:check/backend/landing/clean。

**重要环境结论**：`ntc ran <target>` 在 Git Bash 里会挂起（需要 ConPTY），必须用 PowerShell / Windows Terminal。
`ntc ran check`（内置校验）和 `ntc ran list` 在 Git Bash 里正常。

**index.html**：重写为落地页（品牌红 #E02E24 + 米白，纯 CSS 手机样机、功能九宫格、性能前后对比、
四条演示路径、终端 + ntc 命令清单、目录树）。`.reveal` 动画只在 `<html class="js">` 下生效，
无 JS 时内容仍可见。用 `npx playwright screenshot` 逐屏核对过布局（1280 与 390 宽）。
