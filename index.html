Features

买家链路里的每一步都有页面

主包放首页、分类、购物车、我的、搜索与商品详情；结算、地址、订单进 packageOrder， 增长玩法进 packageGrowth，收藏进 packageUser，按需加载。

🏠

首页

轮播、八宫格分类、限时秒杀横滑、拼团热卖、猜你喜欢，首屏骨架屏 + 下拉刷新。

🔍

分类与搜索

分类侧栏联动、关键词搜索、热搜词，按销量与价格双向排序。

🧾

商品详情

多图轮播、SKU 弹层、库存与数量校验、评价、店铺、收藏、活动入口一屏收齐。

🛒

购物车

单选 / 全选、加减数量、删除、库存夹取，角标数量随操作实时刷新。

💳

下单与支付

地址选择、运费规则（满 99 免运费）、自动匹配最优优惠券、模拟支付落单。

📦

订单

状态筛选、订单详情、取消、确认收货与物流时间线，订单数据持久化在本地。

🤝

增长玩法

拼团（模拟好友参团）、砍价（模拟帮砍一刀）、限时秒杀、领券中心、邀请有礼。

👤

个人中心

订单入口与状态计数、收藏、优惠券、地址簿、客服，全部本地可操作。

🧩

组件化

goods-card、price-tag、countdown、empty-state、自定义 tabBar 复用到底。

Performance

打开更快：图片不再等网络

之前每个商品图都指向 picsum.photos 的随机种子，一次首页要发几十个图片请求， 图还经常和商品对不上。现在换成离线生成的渐变封面 + 商品 emoji，图片与商品一致，也不再受网络影响。

0首屏网络图片请求
~630 B单张封面体积（内联）
100%图片与商品对得上
−69%列表 setData 负载

之前 随机占位图

  • 每件商品 4 个 picsum.photos 请求，首页一次几十个
  • 图是随机风景照，和商品毫无关系
  • 弱网下图慢慢刷出来，列表看起来像卡住
  • 列表接口把 images[]、SKU、评价一起塞进 setData（约 83 KB）

现在 生成封面

  • 封面是 16×16 渐变 PNG 的 data URI，秒出、离线可用
  • 按品类配色 + 商品 emoji，一眼能看出是什么货
  • 不用配置图片域名白名单，也不需要 CDN
  • 列表只回卡片字段，重字段留给详情页（约 26 KB）
Demo flows

四条可以直接演示的路径

全部逻辑在 miniprogram/services/mockApi.ts 里，好友参团与帮砍用虚拟用户模拟， 真实版本交给服务端校验。

拼团

详情页发起拼团 → 拼团详情 → 模拟好友参团 → 支付 → 成团，订单自动关联团单。

首页 → 商品 → 发起拼团

砍价

多次「帮砍一刀」把价格砍到底价，砍到底后可直接按底价下单。

商品 → 发起砍价

秒杀

限时场次带倒计时与库存进度条，售罄或结束会自动禁用抢购按钮。

首页 → 限时秒杀

优惠券

领券中心领取后，结算时按门槛自动匹配最优券，锁定、核销、退回状态齐全。

首页 → 领券中心
